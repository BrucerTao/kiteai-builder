## Context

**问题（根因已定位到行号）**：`templates/typescript-express/src/index.ts:67` 写的是
`new URL(req.originalUrl.replace(/^\/v1/, ""), upstream)`。按 WHATWG URL 规范，以 `/` 开头的
引用会**整体丢弃** base 的 path，于是 `UPSTREAM_URL=https://api.open-meteo.com/v1` + 请求
`/v1/forecast` → 上游收到 `/forecast` → 404（真实端点是 `/v1/forecast`）。TS 模板因此只配得通
「真实端点落在根路径」的上游。

Go 模板不受此限（`templates/go-gin/main.go:75,103-104` 的
`httputil.NewSingleHostReverseProxy` 默认 director 用 `singleJoiningSlash` 拼接 base path），
且已被 frankfurter-fx 的生产部署实证。**两模板行为不一致，违反 ARCHITECTURE.md 第 8 节不变量**，
示例服务 `open-meteo-weather` 因此停在 `draft`。

**目标**：把 TS 修到与 Go 一致（保留并拼接 base path）→ 服务复活 → 部署 Render 公网（原生 Node，
不做 Docker）→ **testnet** 真实付费 + 反向不结算 → manifest 转 `testnet` → commit/push（经确认）。
这即是本周看板方向 01 `x402-service` 所需的实质代码推进。

## 根因修复（核心，一行）

**对齐方向：TS → Go。** Go 行为已被 frankfurter-fx 生产实证；反过来改 Go 丢弃 base path 既降能力
又会打断线上部署。

`templates/typescript-express/src/index.ts:67` 改为：

```ts
// Join the upstream base path (same semantics as the Go template's reverse
// proxy): a root reference like "/forecast" would discard UPSTREAM_URL's path.
const target = new URL(upstream.pathname.replace(/\/+$/, "") + req.originalUrl.replace(/^\/v1/, ""), upstream);
```

- 原理：把 base path 亲手拼进「绝对路径引用」后再交给 `new URL`，丢弃规则便不再影响结果；
  `upstream.pathname` 去掉尾部 `/` 保证恰好一个斜杠，等价于 Go 的 `singleJoiningSlash`。
- 查询串：`originalUrl` 自带 query，URL 解析天然保留（现状亦如此）。`UPSTREAM_URL` 本身的查询串
  两边都不定义，文档注明别用。
- 向后兼容：`UPSTREAM_URL` 为根地址（pathname `/` → 拼接为空）时行为与旧版完全一致；当前没有
  任何 live 的 TS 服务，无部署回归风险。
- 语义统一为：`/v1/<path>` 代理到 `join(UPSTREAM_URL 的 path, /<path>)`；**带前缀的上游把前缀
  写进 `UPSTREAM_URL`**（如 `https://api.open-meteo.com/v1`）。

**不变量的落地方式**：

- 「服务目录与模板逐字节相同」（ARCHITECTURE.md:99）：修 TS 模板 → 原样拷贝到
  `services/open-meteo-weather/src/index.ts` → `diff` 断言相同。`kite.ts` 两边都不动。
- 「两模板行为一致」：本轮是**向 Go 既有行为对齐**（Go 已被 frankfurter-fx 生产实证，零改动即
  一致），因此不触发「同一 PR 改两边」的同步义务；按用户指示 Go 模板整个目录不碰（含其
  README / `.env.example`）。该判断写入 ARCHITECTURE.md 第 9 节修复说明，避免后人误读。
- ARCHITECTURE.md 第 9 节相关已知问题与 AGENTS.md 同步改写为「已修复」。
