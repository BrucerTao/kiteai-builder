## Context

活动方向仍是看板 **01 `x402-service`**，第 4 周需要一个有实质内容的推进。上周修完 TS 模板的
base-path 缺陷并把 `open-meteo-weather` 送上了公网 testnet，本轮把同一条已验证的路径**再走一遍、
产出目录里第 3 个服务**：`services/usgs-earthquakes`（TypeScript 模板），把 USGS 地震目录
（FDSN event API）包成按次付费的 x402 服务。

**为什么选 USGS 地震目录**（本轮亲测，见下节）：

- **条款最干净**：USGS 信息属公共领域，可无限制使用（含商用/转售），只要求署名。这正好补上
  `open-meteo-weather` 的短板 —— Open-Meteo 免费档写明**仅限非商业用途**（见「附带发现」）。
- **无 key、无公开速率限制**，单次查询上限 20000 条；上游稳定、返回体是标准 GeoJSON。
- **有干净的 400 触发器**（`starttime=not-a-date` / `format=banana` / `limit=99999` / 未知参数），
  验收标准 2 的反向不结算好证明。
- **数据本身值得按次付费**：实时地震目录是模型离线拿不到的东西，符合 ARCHITECTURE §7「选一个
  值得付费的 API」。

**与上周的关系**：TS 模板的 `index.ts:69` 已按 Go 语义拼 base path，所以
`UPSTREAM_URL=https://earthquake.usgs.gov/fdsnws/event/1` + 本服务 `/v1/query` → 上游
`/fdsnws/event/1/query`，**零代码改动即可配通**。本轮因此是「配置而非分叉」的教科书案例：
`services/usgs-earthquakes/src/` 必须与模板 `src/` **逐字节相同**（ARCHITECTURE.md:99 不变量）。

**本轮不碰模板的理由**：唯一的代码级诱惑是拦掉 `jsonerror=true`（见「jsonerror 陷阱」），但那
要么破坏「服务 src 与模板逐字节相同」，要么触发「改一个模板必须在同一 PR 改另一个」的同步义务
（Go 侧上周明确不碰）。因此改用**文档 + manifest `pitfalls`** 处理，零代码风险。

## 执行前实测事实（2026-10-11 亲测，非沿用旧结论）

### 上游 USGS FDSN event API（`api: 2.8.1`）

| 请求 | 结果 |
|---|---|
| `GET .../event/1/query?format=geojson&starttime=2026-10-01&endtime=2026-10-07&minmagnitude=5.5&limit=5&orderby=magnitude` | **200**，3565 B，0.9 s，4 个 feature（M5.9 印尼 Tambolaka、M5.8 俄 Vilyuchinsk、M5.8 Severo-Kuril'sk、M5.5 阿拉斯加 Aleneva） |
| 同上但 `format=csv` | **200** |
| `format=banana` | **400** `text/plain`：`Bad format value "banana". Valid values are: "quakeml","geojson","csv","kml","kmlraw","xml","text","cap"` |
| `starttime=not-a-date` | **400** `text/plain`：`Bad starttime value ... Valid values are ISO-8601 timestamps` ← **本轮反向测试用这个** |
| `limit=99999` | **400**：`Valid values are 0 <= limit <= 20000` |
| 未知参数 `zzz=1` | **400**：`Unknown parameter "zzz"` |
| `.../event/1/count?format=geojson&starttime=2026-10-04&minmagnitude=6` | **200** `{"count":4,"maxAllowed":20000}` ← 可选第 2 个 endpoint |

**⚠️ jsonerror 陷阱（实测确认）**：加 `jsonerror=true` 后，**查询参数错误会变成 HTTP 200**——
`format=geojson&starttime=not-a-date&jsonerror=true` → `200 application/json`
`{"metadata":{"status":400,"title":"Search Error","count":0,"error":"Bad starttime value ..."}}`；
`limit=99999&jsonerror=true` 同样 200。本 wrapper 的结算判据是**上游 HTTP 状态码 < 400**，
所以带 `jsonerror=true` 的失败查询**会被收费**（协议上没违规，但对买方是坑）。
例外：`format=banana&jsonerror=true` 仍 400（format 解析在前）。
→ 对策：写进 README + `pitfalls`，**不改代码**。
