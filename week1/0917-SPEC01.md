## Context

目标是 Kite AI Bounty **方向 01 `x402-service`**：把 HTTP API 包装成可发现、可调用的
x402 付费服务，未付费返回 402，按 `verify → upstream → settle` 结算，只在上游成功时收费。

本轮范围：**先在 Kite 测试网跑通真实付费交易**，并**验证同一份 wrapper 代码切到主网时
的链参数 / EIP-712 / 金额精度逻辑正确**。公网 https 部署与看板提交（验收第 7 步的公网抓取、
状态转 `testnet`）**推迟到下一轮**。

> ⚠️ **执行后修正（详见文末「执行结果」）**：原计划假设「本地用 kpass agent 打
> `http://localhost:8080` 就能完成 testnet 真实付费调用」是**错的**。`kpass agent:session
> execute` 由 Passport 后端**服务端抓取** merchant URL（CLI 只上传 `url`+`method`+`body_hash`+
> `headers_hash`+`session_id`+`nonce`，不含请求体），且 agent 的 EVM 私钥是**后端托管**的
> （`.kite-passport/agent.json` 里只有 `agent_token` JWT，没有私钥）。所以后端既够不到
> localhost（execute 直接回 `invalid request` / HTTP 400，本地服务日志无任何请求），本地也拿不到
> agent 私钥。本轮改用**自建本地付款钱包 + x402 Go SDK 客户端**（EIP-3009 签名）直接对
> `http://localhost:8080` 完成真实 testnet 付费调用——链上结算、收款方、金额与协议流程与
> kpass 路径完全一致，只是付款方换成我们自持私钥的钱包。**结论：真实付费调用（验收第 7 步）
> 必须 merchant 公网 https 可达；localhost 只能验证到「自建付款方」这一层。**

## 选型决策

- **模板：Go (`templates/go-gin`)**。理由：`httputil.NewSingleHostReverseProxy` 的 director 会
  正确拼接 base path，带前缀的上游（`/v1/...`）也能配通；TS 模板有根路径限制（`new URL("/x", base)`
  会丢弃 base path，示例服务 `open-meteo-weather` 因此 404 仍是 `draft`）。本机 Go 1.27 已由 `g` 管理。
- **上游：Frankfurter（ECB 汇率，免费、无需 key、条款宽松）**。服务名 `frankfurter-fx`。
  端点 `GET /v1/latest?base=USD`（真实上游 `https://api.frankfurter.dev/v1/latest`）。
  实施第一步用 `curl` 实测确认 host/path 后再钉死配置；若 path 或条款不合适，回退到
  Open-Meteo（同样走 Go，prefix path 在 Go 下可用）。
  > 上线前需复核 `upstream.terms_url` 是否允许代理 / 转售，本轮（draft / 本地）不阻塞。

## 执行步骤

### Phase 0 — 前期准备（领水、钱包、工具）
1. 装 kpass：`curl -fsSL https://cli.gokite.ai/install.sh | bash`；`kpass --version` 有输出。
   - 用 `kpass --help` 确认命令是冒号还是空格分隔（官方文档 `agent:register`，README 写空格，以 help 为准）。
2. 非交互 shell 里先 `. "$HOME/.g/env"`（只有交互式 zsh 会自动加载）；`go version` 正常。
3. `kpass` 登录，拿到一个 Kite 钱包地址作为 `PAY_TO`（收款方）。
4. 领水（testnet pieUSD）：`kpass faucet drop --recipient <PAY_TO> --token pieUSD`
   或网页 <https://faucet.gokite.ai>。
5. `kpass wallet balance` 确认 pieUSD 有余额（chain id 2368，token `0x38129cf4CE5E183eFF248F42A7D345Bb1B47621A`，18 位精度）。

### Phase 1 — 脚手架
6. 拷贝 `templates/go-gin/` → `services/frankfurter-fx/`；删掉拷贝来的已编译二进制 `go-gin`（本地重新 build）。
7. 先 `curl -i "https://api.frankfurter.dev/v1/latest?base=USD"` 实测确认真实 host/path 与返回体。
8. 写 `services/frankfurter-fx/.env`：
   ```
   PAY_TO=<你的 Kite 钱包地址>
   KITE_NETWORK=testnet
   UPSTREAM_URL=https://api.frankfurter.dev/v1
   PRICE_USD=0.001
   SERVICE_DESCRIPTION=ECB foreign-exchange rates wrapped as an x402 paid service on Kite
   PORT=8080
   ```
9. `cd services/frankfurter-fx && go build ./... && go vet ./...` 通过。

### Phase 2 — 本地 402 验证（testnet）
10. 启动：`set -a && source .env && set +a && go run .`（或 build 后运行二进制）。
11. `curl -i http://localhost:8080/healthz` → 200，body 显示 network/asset/price。
12. `curl -i "http://localhost:8080/v1/latest?base=USD"`（无付费头）→ **402**，带 `PAYMENT-REQUIRED` 头。
13. base64 解码该头，断言：`accepts[0].network == "eip155:2368"`、`extra.name == "pieUSD"`、
    `extra.version == "1"`、`amount == "1000000000000000"`（0.001 × 10^18）。

### Phase 3 — testnet 真实付费调用（验收第 7 步的本地等价）
14. `kpass sandbox on`（如需要）。
15. `kpass agent register` → `kpass agent session create`（设消费上限）→
    `kpass agent session execute` 打 `http://localhost:8080/v1/latest?base=USD`。
16. 期望：HTTP 200 + 上游汇率 body + 结算交易哈希。
17. 在 <https://testnet.kitescan.ai> 查该哈希，确认收款方 == `PAY_TO`。保留输出作为证据。

> ⚠️ **实际执行**：第 15 步的 `kpass agent:session execute` 对 localhost **不可用**（后端服务端

### 关键修正：kpass execute 打不了 localhost（原 Phase 3 假设有误）
拦截 `kpass agent:session execute` 的实际请求证实：CLI 只向后端 POST
`/sandbox/v1/agent/session/execute`，body 为
`{url, method, body_hash, headers_hash, session_id, nonce}`——**不含请求体**，由后端**服务端
重建并抓取** merchant URL；且 `.kite-passport/agent.json` 只有 `agent_token`(JWT)，**EVM 私钥后端
托管**。因此：
- 打 `http://localhost:8080/...` → 后端直接回 `invalid request`(HTTP 400, exit 2)，本地服务日志
  **零请求**（连免费的 `/healthz` 也一样失败）→ 后端根本够不到 localhost。
- 本地也拿不到 agent 私钥，无法用 agent 身份自建付款。
- **推论**：真实付费调用（验收第 7 步）必须 merchant **公网 https** 可达，下一轮部署后才能用
  kpass 复跑。本轮用自建付款方在 localhost 完成了等价的链上真实结算。

### 本轮实际付费方：`fxpayer`（throwaway，置于 `/tmp/fxpayer`，不入库）
基于 merchant 同款 x402 Go SDK 客户端（`signers/evm` + `mechanisms/evm/exact/client` +
`http.Newx402HTTPClient.GetWithPayment`），用自持私钥的新钱包签 EIP-3009
`transferWithAuthorization`；pieUSD 走 EIP-3009（facilitator 代付 gas，付款方无需 KITE）。

  （tx `0xba0c94986da253ce674212659dfb1e7e197d0cc51fa7858961e2a448ee0adf32`），链上余额 100.0 已确认。
