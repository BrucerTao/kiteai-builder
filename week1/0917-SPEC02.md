## Context

SPEC01 已在**本地**验证 `services/frankfurter-fx`：未付款 402 头参数全对、自建付款方完成真实 testnet
链上结算（收款方 == `PAY_TO`，0.001 pieUSD）、上游 4xx 不结算、主网 402 头编码正确（`eip155:2366` /
USDC.e / amount=1000，未花真钱）。

**唯一缺口**：`kpass agent:session execute` 由 Passport 后端**服务端抓取** merchant URL、agent 私钥
**后端托管**，因此打不了 `http://localhost`（实测 `invalid request`）。验收第 7 步的 kpass 真实付费
调用必须在 merchant **公网 https** 可达后才能正跑。

本轮：① 部署公网 https + 外网复测；② kpass 从公网 URL 跑真实 testnet 付费 + 反向不结算；③ 更新
manifest（`status: testnet` + `base_url` + 真实 `maintainer.github`）；④ 修复仓库归属并提看板。主网真实
USDC.e 结算 = 可选 **Track B**（需显式出资 + 授权，本轮默认不花真钱）。

## 决策点（需用户确认）

1. **托管平台 → 已定：Render 免费版**（用户要求免费、不绑卡）。约束：公网 https、禁 localhost/http/自签/
   浏览器验证型隧道、后端纯 HTTP 服务端抓取（不能有 cookie/JS challenge）。Render 免费档用现有
   `Dockerfile` + `render.yaml`（Blueprint）部署，自动 `*.onrender.com` 有效 https，env/secret 在面板注入。
   **唯一坑：免费档闲置约 15 分钟休眠、冷启动约 50s** → 每次 kpass 付费调用前先 `curl <HOST>/healthz`
   唤醒（`verify_public.sh` 已内置 warm-up 重试）。Fly.io 改为按量付费需绑卡，故本轮不用。
2. **本轮是否主网真实结算 → 推荐否**。看板方向 01 验收本就是 testnet（pieUSD）；主网要花真 USDC.e。
   Track A（公网 testnet）过验收 + 提看板；Track B（主网 live）仅当用户出资授权再做。
3. **仓库归属（硬门槛）**。当前 `origin` 指向**上游** `gokite-ai/kite-x402-services`，`maintainer.github`
   与 git 身份仍是占位/个人信息。看板校验要求**仓库 owner == 看板绑定的 GitHub 账号**，且
   `git config user.email` 关联该账号、`maintainer.github` 一致 → 必须先改（Phase 0）。

### Dockerfile

```dockerfile
# ---- build stage ----
# 在本机平台构建，交叉编译到部署目标（Render/Fly shared CPU = linux/amd64）
FROM --platform=$BUILDPLATFORM golang:1.25 AS build
ARG TARGETARCH
WORKDIR /src
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN CGO_ENABLED=0 GOOS=linux GOARCH=$TARGETARCH go build -o /out/frankfurter-fx .

# ---- run stage ----
# distroless/static 自带 CA 证书：对 upstream/facilitator/RPC 发 TLS 必需
FROM gcr.io/distroless/static-debian12
COPY --from=build /out/frankfurter-fx /frankfurter-fx
EXPOSE 8080
ENTRYPOINT ["/frankfurter-fx"]
```

`.dockerignore`：`.git`、`.env*`、`.kite-passport/`、`*.key`、`/frankfurter-fx`、`Dockerfile`、`render.yaml`、
`verify_public.sh`、`README.md`、`service.yaml`。配置全走 env（Render 自动注入 `PORT`；其余在 `render.yaml`/面板设），

### Phase 1 — 容器化

### Phase 2 — 部署（Render 免费版）

6. 登录 <https://dashboard.render.com>（用 GitHub 账号 OAuth 最省事，首次需授权 Render 访问该仓库）。
7. **New + → Web Service** → 连接 `BrucerTao/kite-x402-services` → **Root Directory 填
   `services/frankfurter-fx`** → Runtime 自动识别 **Docker**（找到该目录 `Dockerfile`）→ Instance Type
   选 **Free** → **Health Check Path 填 `/healthz`**。

   `KITE_NETWORK=testnet`、`UPSTREAM_URL=https://api.frankfurter.dev/v1`、`PRICE_USD=0.001`、
   `SERVICE_DESCRIPTION=ECB foreign-exchange rates wrapped as an x402 paid service on Kite`、
   `PAY_TO=<PAY_TO>`。
9. **不要设 `PORT`**：Render 自动注入；`main.go` 已绑 `0.0.0.0:$PORT`（实测 `addr := ":" + env("PORT","8080")`）。
10. Deploy 完成后记下公网地址 `https://frankfurter-fx.onrender.com`（= `<HOST>`）。

### Phase 3 — 外网复测（验收 step 5）
> 自动路径：`cd services/frankfurter-fx && ./verify_public.sh <HOST>`。它会**先 warm-up**（免费档冷启动重试
> 至 `/healthz` 200）→ 断言未付款 `/v1/latest` 402 → base64 解码断言 4 项 testnet 参数 → 打印 Phase 4/5
> 的 kpass 命令。不花钱、不发起付费调用。手动等价：
10. `curl -i https://<HOST>/healthz` → 200（network `eip155:2368` / pieUSD / price）。
11. `curl -i "https://<HOST>/v1/latest?base=USD"`（无付费头）→ 402 + `PAYMENT-REQUIRED`；base64 解码断言
    `network=="eip155:2368"`、`extra.name=="pieUSD"`、`version=="1"`、`amount=="1000000000000000"`。
    `curl` 直接拿到 402 即证明无浏览器验证、后端可服务端抓取。

### Phase 4 — kpass 真实付费（公网，验收 step 7 正跑）
> **执行记录（2026-09-18）**：✅ **已完成**，但走的是 fxpayer2 自建 payer（kpass 账号登录受阻：
> 旧会话 401、注册邮箱 login init 报 email not registered、signup 验证码邮件已发待用户输入，
> 且 prod 后端 faucet 已关闭）。fxpayer2 = SPEC01 fxpayer 的宽签名窗口版（validAfter 回拨
> 600s→2h，绕开**Kite 测试网链头滞后 ~30 分钟**导致的 `AuthorizationNotYetValid` revert ——
> SDK 默认窗口的支付当前全部无法结算，kpass 同样会中招，待链恢复）。
> 结果：`https://frankfurter-fx.onrender.com/v1/latest?base=USD` → **200 + 完整 ECB 汇率 body**；
> 结算 tx `0x186f8e2090d80f39b0b83883bf3351e0085368fd6a1ad4c08ca2a5f554b9336f`（block 22041165，
> RPC 实证 from=payer → to=PAY_TO、0.001 pieUSD；kitescan 可查）。余额对账：payer 99.997、
> PAY_TO 0.003（三笔结算 × 0.001 分毫不差）。完整过程见 `evidence2.md` §12。
> 命令语法已对 **kpass 1.10.1 `--help`** 核实：用**冒号**形式（`agent:register`、`agent:session create`
> /`status`/`use`/`execute`）；README 的全空格写法错误；**无 `sandbox` 命令**（SPEC01 的 `kpass sandbox on` 已废弃）。
12. 预检 + 登录（交互式，需你的邮箱 OTP）：
    `kpass health` → `kpass me`；未登录则 `kpass login init --email <YOUR_EMAIL>` → `kpass login verify --login-id <id> --code <OTP>`。
13. 资金：付款方需 testnet pieUSD —— `kpass wallet address` 取地址 → `kpass faucet drop --recipient <PAYER_ADDR> --token pieUSD`
    → `kpass wallet balance` 确认到账。
14. 建会话（**需审批**）：`kpass agent:register --type <type>` → `kpass agent:session create --max-amount-per-tx <amt> --ttl <dur> [--max-total-amount <amt>] [--assets pieUSD]`
    → `kpass agent:session status --request-id <id> --wait`（轮询审批）→ `kpass agent:session use --session-id <id>`。
15. **先唤醒**（Render 免费档会休眠）：`curl -s https://<HOST>/healthz` 等到 200，紧接着执行付费调用：
    `kpass agent:session execute --url "https://<HOST>/v1/latest?base=USD"`
    （后端服务端抓取 → 必须公网 https，对照 SPEC01 localhost 失败）。期望 200 + 真实汇率 body + 结算交易哈希。
16. 链上核对：`kpass wallet balance` 看扣费；`testnet.kitescan.ai` 查哈希 → pieUSD `Transfer` 收款方 == `PAY_TO`、0.001。保留输出作看板材料。

### Phase 5 — 反向不结算（公网，验收 step 8）
